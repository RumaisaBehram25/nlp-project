NLP project · Log anomaly detection

Can a model that reads the meaning of logs survive change?

We trained five detectors on two real system logs (HDFS and BGL), then made the test harder: noisy logs, reworded messages, and a system the models had never seen.

How it works

1

Parse

Drain turns raw lines into templates. Receiving block blk_1 from 10.0.0.1 becomes Receiving block <*> from <*>.

2

Group

HDFS: all events of one block. BGL: windows of 20 lines. A group is anomalous if it contains a failure.

3

Represent

Each template becomes an event ID, or an SBERT vector that stands for what the message means.

4

Detect

Five detectors read each group and say normal or anomaly. Scores are for the anomaly class only.

What rewording looks like

A software update changes the wording of a message. A model that only knows IDs sees a brand-new event. SBERT still sees nearly the same meaning.

beforeReceiving block <*> src: <*> dest: <*>
aftergetting data chunk <*> src: <*> dest: <*>
beforeReceived block <*> of size <*> from <*>
aftergot data chunk <*> of size <*> from <*>
before<*> Served block <*> to <*>
after<*> delivered data chunk <*> to <*>
beforeBLOCK* NameSystem.allocateBlock: <*> <*>
afterEvent: BLOCK* NameSystem.allocateBlock: <*> <*>

SBERT similarity

Mean cosine similarity, from the embedding step.

The rewording is rule-based (a small synonym list), not written by a language model. It is a fair first test, not a copy of real software updates.
